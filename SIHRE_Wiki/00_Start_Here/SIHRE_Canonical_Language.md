# SIHRE Canonical Language

This is the authoritative reference for SIHRE naming, positioning, and key definitions. All public-facing content must use this language consistently.

## Project Name

**SIHRE — Self-Improving Heterogeneous Reasoning Ensemble**

## One-Line Description

SIHRE is a meta-orchestrated framework for governing heterogeneous reasoning systems under uncertainty, drift, and non-stationarity.

## Expanded Description

SIHRE is a framework for coordinating multiple reasoning modalities through a meta-orchestrator that manages trust, uncertainty, verification, memory, and adaptation over time.

## Whitepaper Title

SIHRE: Meta-Orchestrated Heterogeneous Reasoning for Adaptive Intelligence Under Non-Stationarity

## Definition of Self-Improving

In SIHRE, "self-improving" refers to bounded updates to memory, expert trust, routing preferences, evaluation feedback, and research priorities. It does not imply unrestricted autonomous self-modification of objectives, safety constraints, or system goals.

## Terms to Avoid in Public Content

- SIHRE-13 as the public name
- fixed modality count (e.g., "13 signals", "13 modalities")
- universal intelligence
- guaranteed reliability
- unrestricted self-modification
- trading-specific examples
- finance/alpha/strategy/execution references
- NeuroFusion implementation details
- proprietary schemas, weights, or thresholds
- private benchmarks

## Positioning Guidelines

SIHRE should be described as:
- **meta-orchestrated** — governed by a meta-orchestrator, not just aggregated
- **heterogeneous** — coordinates diverse reasoning modalities, not just model variants
- **domain-general** — applicable across robotics, cyber defense, logistics, scientific discovery, climate-risk, healthcare
- **uncertainty-aware** — quantifies and manages uncertainty rather than forcing confidence
- **drift-aware** — adapts to changing environments and non-stationarity
- **governed** — focused on reasoning governance, not just model ensembling

Use "meta-orchestrated" as a positioning phrase, not as part of the acronym.

## Public-Safe Domain Examples

When illustrating SIHRE applications, use these domain-general examples:
- Robotics (changing terrain, imperfect sensors, competing planners)
- Industrial monitoring (sensor anomalies, maintenance history, failure simulation)
- Cyber defense (event triage, log correlation, false positive challenges)
- Logistics (disruption adaptation, demand uncertainty, resource constraints)
- Scientific discovery (experiment prioritization, hypothesis generation, belief updating)
- Climate-risk systems (model ensembles, scenario analysis, uncertainty estimation)
- Healthcare decision support (diagnostic reasoning, treatment planning)

**Never use** trading, finance, alpha generation, portfolio, or strategy examples in public content.
